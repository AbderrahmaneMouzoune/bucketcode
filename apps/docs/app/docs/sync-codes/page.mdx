# Sync codes

A sync code is the whole user experience of moving between devices: it appears on the old phone,
and the user types it into the new one. Everything about it is shaped by that.

```ts
import { createSyncCode, normalizeSyncCode } from 'bucketcode'

createSyncCode() // "K7QP2M4X"
normalizeSyncCode('k7-qp2m4x') // "K7QP2M4X"
```

## The alphabet

Codes use [Crockford base32](https://www.crockford.com/base32.html):

```
0123456789ABCDEFGHJKMNPQRSTVWXYZ
```

`I`, `L`, `O` and `U` are absent. The first three because they are the characters people misread —
`I` for `1`, `O` for `0`, `L` for `1` — and `U` so a random code cannot spell something
unfortunate.

`normalizeSyncCode()` then folds the confusions on the way back in: `O` reads as zero, `I` and `L`
as one, case is ignored, and spaces and dashes are dropped. So all of these find the same
snapshot:

```ts
normalizeSyncCode('K7QP2M4X') // "K7QP2M4X"
normalizeSyncCode('k7qp2m4x') // "K7QP2M4X"
normalizeSyncCode('K7-QP2M-4X') // "K7QP2M4X"
normalizeSyncCode('OIL5ABCD') // "0115ABCD"
```

Call it on user input before you look anything up, and let it throw: a code with a character
outside the alphabet cannot possibly exist, so `INVALID_SYNC_CODE` is a better answer than a
lookup that returns nothing.

```ts
try {
  const code = normalizeSyncCode(typed)
  return await bucket.getSnapshot(code)
} catch (error) {
  if (isBucketCodeError(error) && error.code === 'INVALID_SYNC_CODE') {
    return Response.json({ error: 'That does not look like a code' }, { status: 400 })
  }

  throw error
}
```

## How guessable is it

Eight characters of base32 is 40 bits — about 1.1 × 10¹² codes. That is not a secret, and you
should not treat it as one. What makes it safe enough is that a live code is a needle in that
haystack **for a short window**:

- Give every transfer code a short `expiresIn`. An hour is generous; a working transfer takes a
  minute.
- Rate-limit the lookup route. Without a limit, an attacker gets unlimited attempts; with one, the
  arithmetic stops being interesting.
- Pass `ifAbsent: true` on write, so a generated code that happens to be taken fails loudly
  instead of overwriting somebody else's snapshot.

```ts
await bucket.putSnapshot(code, state, { expiresIn: 60 * 60, ifAbsent: true })
```

Longer codes are one argument away when the trade is worth it:

```ts
createSyncCode(12) // 60 bits, still typable
```

## A code is a bearer token

Anyone holding a live code can read that snapshot. That is inherent: the receiving device has no
account, no session and no keys — the code _is_ the authentication. Which means:

- Do not log codes, and keep them out of URLs you send to analytics.
- Do not reuse one code for repeated syncing. Generate a new one per transfer.
- If the data is genuinely sensitive, do not rely on the code at all: encrypt in the browser
  before it reaches your server. See [end-to-end encrypted sync](/docs/use-cases/encrypted-sync).

For a continuous per-account backup, skip codes entirely and key the snapshot by user id behind
your normal session check — see [continuous backup](/docs/use-cases/continuous-backup).

## Codes are keys, not magic

A code is just an object key, so everything else in the package applies to it. It goes through the
same validation as any key, and the configured `prefix` applies:

```ts
const bucket = createBucket({ bucket: 'my-bucket', prefix: 'snapshots' })

await bucket.putSnapshot('K7QP2M4X', state) // stores snapshots/K7QP2M4X
await bucket.delete('K7QP2M4X') // deletes it, once the transfer is done
```

Deleting a code after a successful restore is a good habit: the transfer is over, and the token
should stop working.
