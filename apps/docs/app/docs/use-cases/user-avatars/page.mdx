# User avatars

An avatar is the simplest case of one file per identifier: the identifier is the user id, the
bucket is public behind a CDN, and there is no download route at all — the URL goes straight into
an `img` tag.

```ts
import { createBucket } from 'bucketcode'

export const avatars = createBucket({
  bucket: process.env.S3_BUCKET,
  prefix: 'avatars',
  publicUrl: 'https://cdn.example.com',
  maxSize: 2 * 1024 * 1024,
})
```

With `publicUrl` set, `upload()` and `put()` return a ready-to-use `url` and `getUrl()` stops
signing.

## Uploading

```ts
// app/api/me/avatar/route.ts
import { auth } from '@/lib/auth'
import { db } from '@/lib/db'
import { avatars } from '@/lib/avatars'

const ALLOWED = new Set(['image/png', 'image/jpeg', 'image/webp'])

export async function POST(request: Request) {
  const session = await auth()
  if (!session) return new Response('Unauthorized', { status: 401 })

  const form = await request.formData()
  const file = form.get('avatar')

  if (!(file instanceof File)) {
    return Response.json({ error: 'Missing file' }, { status: 400 })
  }

  if (!ALLOWED.has(file.type)) {
    return Response.json({ error: 'PNG, JPEG or WebP only' }, { status: 415 })
  }

  const result = await avatars.put(session.userId, file, {
    cacheControl: 'public, max-age=31536000, immutable',
  })

  await db.user.update({ where: { id: session.userId }, data: { avatarVersion: result.etag } })

  return Response.json({ url: result.url })
}
```

`file.type` comes from the browser and is not proof of anything. Treat it as a cheap first filter
and, if the bucket is public, verify the actual bytes with a magic-number check before storing
them.

## Cache busting

The key never changes, which is what makes replacement clean — and exactly what makes the CDN
serve a stale image. Two ways out:

**Version the URL.** Store the ETag returned by `put()` and append it as a query string. The CDN
treats it as a distinct URL, the object stays at one key:

```tsx
<img src={`${user.avatarUrl}?v=${user.avatarVersion}`} alt="" />
```

**Or drop `immutable`.** Set a short `cacheControl` such as `public, max-age=60` and accept a
minute of staleness. Simpler, and fine for most products.

The one thing not to do is put the version in the key. That brings back the orphan objects the
one-file-per-id shape exists to avoid.

## Removing an avatar

```ts
await avatars.delete(session.userId)
await db.user.update({ where: { id: session.userId }, data: { avatarVersion: null } })
```

Fall back to a generated placeholder when `avatarVersion` is null, rather than storing a default
image for every user.
